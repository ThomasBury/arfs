# 06 — Utilities, plots, datasets, and documentation workflows

Reviewed commit: `03f67d0a54b69fac5ddbb83e306c8e8e72e2d3a2`, on 2026-10-11. Scope is the remaining utilities, dataset loaders/generators, plot presentation, public documentation claims, and bounded notebook workflows. **Findings, ranked by consequence**

- **F1 — Category encoding collapses distinct values and fails on missing categories with newer pandas. P1; small remedy.** [utils.py](../src/arfs/utils.py), lines 213–221. `get_pandas_cat_codes` stringifies values before encoding. Integer `1` and string `'1'` receive the same code in both snapshots. On frozen pandas, missing values also collide with literal `'nan'` or `'None'`; on newer pandas those missing-value fixtures instead raise a string/float sorting `TypeError`. See `test_encoding_preserves_distinct_values`. Callers include shared importance fitting, BoostAGroota, and GrootCV. Use pandas category/factorization semantics with an explicit missing-value policy, preserving distinct original values. Coordinate caller ownership with unit 1B F5; this is a distinct value-loss defect, not a repeat of its input-mutation finding.

- **F2 — Target-versus-feature plots crash or repeat the wrong predictors. P1; small remedy.** [utils.py](../src/arfs/utils.py), lines 663–679. The loop overwrites the feature label with the subplot column number. Four string-named features raise `KeyError: 0`; integer columns `[0,1,2,3]` produce panels for `[0,1,0,1]`. A single subplot raises `TypeError`, and a single row of subplots raises `IndexError` because axes are squeezed. Four cases in `test_target_plot_uses_each_feature` cover these paths. Keep the feature label separate from subplot coordinates and request a consistently two-dimensional axes array. The [rendered counterexample](evidence/06-utilities-and-workflows/frozen-plots/target-integer-columns.png) visibly repeats both titles and data.

- **F3 — Leshy colors boxes by importance rank rather than actual selection membership. P1; small remedy.** [allrelevant.py](../src/arfs/feature_selection/allrelevant.py), lines 365–387. After sorting mean importance, the plot assumes the highest boxes are confirmed and the next boxes tentative. The controlled fixture has a selected feature with history `[1,1,1]` and a rejected feature with `[0,10,0]`; the latter becomes blue/confirmed and the former gray/rejected. See `test_leshy_plot_colors_match_support` and the [inspected plot](evidence/06-utilities-and-workflows/frozen-plots/leshy-membership.png). Map masks by feature name after sorting, following GrootCV's existing membership-based approach. Unit 1B's overlapping tentative/support semantics also need resolution; importance magnitude alone cannot define the legend categories. No frequency of this mismatch in real fits was measured.

- **F11 — Association plotting uses an unavailable SciPy namespace. P1; small remedy.** [association.py](../src/arfs/association.py), line 2119; shared callers at 2321 and 2410. `sch.distance.pdist` works in SciPy 1.13.1 but raises `AttributeError` in the installed 1.18.1 snapshot, even for an ordinary finite 3-by-3 matrix. `test_association_sign_order_annotations_and_owner` passes frozen and fails newer. Use the documented `scipy.spatial.distance.pdist` import. SciPy's [distance API source](https://github.com/scipy/scipy/blob/main/spatial/distance/_distance.py) describes its condensed-distance output, which linkage accepts. This affects direct static plotting, `CollinearityThreshold.plot_association`, and the clustering path of the optional interactive plot. The interactive backend itself was not installed or rendered.

- **F12 — The classification tutorial uses an undefined variable in its first fit. P1; small remedy.** [classification notebook](../docs/notebooks/arfs_classification.ipynb), zero-based JSON cell 11, uses `X_encoded`, which is only assigned much later in cell 46. The earlier data cell creates `X`. After excluding optional comparison-backend imports and substituting local cancer data for remote Titanic, the unchanged fit cell raises `NameError` in both snapshots. The separate smoke run explicitly supplies numeric `X_encoded` and completes; that is an adjusted excerpt, not a repaired or fully passing notebook. Define the intended encoder and its output before the first fit, and identify optional notebook prerequisites. The [regression notebook](../docs/notebooks/arfs_regression.ipynb), cell 34, also raises `NameError` for the unimported `sklearn_pimp_bench`; this confirms the source issue already handed off by unit 4 and is not counted as another new finding.

- **F4 — Importance plotting fails for the valid threshold 1. P2; small remedy.** [variable_importance.py](../src/arfs/feature_selection/variable_importance.py), lines 265–269. With cumulative shares `[0.6,0.9,1.0]`, searching for a share strictly above 1 leaves an empty array and `np.min` raises. See `test_importance_plot_at_threshold_one`. Handle the terminal boundary explicitly and align the displayed crossing feature with the retained-share contract when unit 3 F1 is repaired. This finding concerns rendering, not a second independent report of the selection cutoff defect.

- **F5 — `plot_n` never limits the plotted features. P2; small remedy.** [variable_importance.py](../src/arfs/feature_selection/variable_importance.py), lines 262–292. A requested two-feature plot displays all three fixture features; the parameter changes only figure height. See `test_importance_plot_respects_limit` and the [three-point result](evidence/06-utilities-and-workflows/frozen-plots/importance-limit-two.png). Slice the ordered display data to the requested count and calculate dimensions from that slice, retaining the full-data cumulative meaning. Otherwise large feature sets remain overcrowded despite an explicit display limit.

- **F6 — The default cumulative-importance plot hides the first feature. P2; small remedy.** [variable_importance.py](../src/arfs/feature_selection/variable_importance.py), lines 291–317. Applying logarithmic scale to categorical x positions removes position zero, where the most important feature lies. The [inspected default plot](evidence/06-utilities-and-workflows/frozen-plots/importance-default-log.png) omits that cumulative point and replaces feature labels with numeric logarithmic ticks. `test_importance_cumulative_plot_includes_first_feature` checks that the first point lies outside the visible x limits. Keep feature positions linear; the importance-value axis can remain logarithmic.

- **F7 — A one-feature association matrix cannot be plotted. P2; small remedy.** [association.py](../src/arfs/association.py), lines 2119–2121 and 2321. Clustering a 1-by-1 matrix passes an empty distance vector to linkage. The frozen case fails with an empty-distance error; newer SciPy fails earlier at F11. See `test_one_feature_association_plot`. Bypass clustering for one feature and explicitly reject an empty matrix before creating a figure. Do not replace an undefined association statistic with a fabricated value merely to render it.

- **F8 — Synthetic generators reset unrelated global randomness but leave weights dependent on prior state. P2; small remedy.** [utils.py](../src/arfs/utils.py), lines 743–747 and 842–846. Both generators draw weights before resetting NumPy's global seed to 42. Changing the caller's seed changes weights but leaves features, targets, and the subsequent random stream identical. The paired generator tests verify all three facts. Use one local random generator for the whole dataset, including weights. The current behavior can unexpectedly couple later train/test splits or randomized fits to a preceding example-data call.

- **F9 — Odd-sized regression datasets cannot be generated. P2; small remedy.** [utils.py](../src/arfs/utils.py), lines 769–774. The high-cardinality column concatenates two arrays of length `int(size/2)`, so `size=11` creates ten entries alongside eleven-row columns and DataFrame construction fails. See `test_odd_size_regression`. Generate exactly `size` category entries while retaining the intended repeated-level pattern; no new configuration is needed.

- **F13 — Both local documentation build launchers point to a nonexistent source directory. P2; small remedy.** [Makefile](../docs/Makefile), line 8, and [make.bat](../docs/make.bat), line 8, set `SOURCEDIR=source`, but `conf.py` and RST files are directly under `docs/`. The [reference ledger](evidence/06-utilities-and-workflows/local-references.json) verifies that `docs/source/conf.py` does not exist. Sphinx [looks for configuration inside its source directory](https://www.sphinx-doc.org/en/master/man/sphinx-build.html). Set the launchers' source to `.`. Actual build attempts stop earlier because Sphinx is absent; this directory defect is source-established, not a claimed observed Sphinx error. `.readthedocs.yml` correctly points at `docs/conf.py`, so this does not prove the hosted build has the same directory fault.

- **F15 — Titanic's `is_alone` marks passengers with one relative as alone. P2; small remedy.** [utils.py](../src/arfs/utils.py), lines 512–514. `family_size` is `parch + sibsp`, excluding the passenger, but the test uses `>1`. The network-free [dataset fixture](evidence/06-utilities-and-workflows/datasets.py) supplies counts 0, 1, 1, and 2; both snapshots return `[1,1,1,0]`, where the one-relative cases should be zero. Compare the relative count with zero, or consistently include the passenger in the family-size definition. The fixture tests feature construction only; no OpenML download or full Titanic benchmark was run.

- **F10 — The input validator rejects its documented NumPy input. P3; small remedy.** [utils.py](../src/arfs/utils.py), lines 273–287. `validate_pandas_input(np.ones((2,2)))` raises because arrays have no `.values`; its error text says arrays are supported. `test_validate_pandas_input_accepts_array` reproduces this in both snapshots. Accept the declared ndarray directly and validate pandas objects explicitly, or remove the unused helper through an intentional public-API decision. No internal source/test caller exists, so this is a lower-priority direct/API-documentation inconsistency.

- **F14 — The README's preprocessing tutorial link is broken. P3; trivial remedy.** [README](../README.md), line 30, links to `docs/notebooks/preprocessingipynb`; the actual file is `preprocessing.ipynb`. The local-reference ledger records this as the only missing README local target. Correct the filename. No documentation rewrite is needed.
